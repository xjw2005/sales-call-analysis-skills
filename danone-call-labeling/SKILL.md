# 达能门店电销打标

从 [README](README.md) 读取输入格式、项目字段和命令。判断依据为 `references/common.md` 及 `references/projects.json` 中当前项目的定义；不要使用通用拜访分析的类目或跨项目套用同编号字段。

- 分析前核对项目、仓库版本和真实字段schema，确认使用的模型与分析范围。模型由用户指定；示例环境使用 `deepseek-flash`，密钥只由运行环境注入。
- 输入是完整、角色已确认且带原始时间戳的转写。渠道专员属于我方坐席，客户原话才能支持客户事实；不按 speaker 编号分配身份。缺少转写或客户话语时留空并复核，不能填成未反馈。
- 每字段独立判断并运行代码校验。默认值不编造引文；C/D级规则、冲突或证据不足留待复核。原句匹配只能确认来源，不能证明语义判断必然正确。
- `pipeline.py` 的模型拒绝、截断或校验失败会停止当前批次，不自动重试。保留失败和已验证产物，避免无差别重跑产生重复费用。
- `field_adapter.py` 只核对三张已绑定副本表并生成非空、无需复核的业务标签草稿，不清空标签、不写生产数据。用户要求清空旧值或实际回填时，另行核对目标、备份并按 Base 写入契约执行，随后读回核验。
- 每组按 `业务标签 → 判断状态（单选）→ 复核原因（多选）→ 依据校验` 展示；见 [四列复核布局](references/review-layout.md)。用已保存结果生成展示，不重新调用模型；完整候选、分析过程和技术错误保留本地。

录音、客户原文、凭证和运行结果保留在被忽略的 `runs/` 或仓库外，不进入公开提交。
