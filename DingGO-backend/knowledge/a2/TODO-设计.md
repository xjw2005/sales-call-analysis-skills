## sop/ 第一批内容需求

> 来源：《DSR 拜访录音分析：行动策略语料库 V2》（https://yuoukuajing.feishu.cn/docx/WHA7dZFhloGaf2xO9IfcxBttn8g ）
> 目的：AI 分析录音时对照这些标准，发现销售没讲清/没做对时，把标准内容主动推送给该销售。
> 以下条目需品牌方补充完善具体内容。

### 1. 实体店价值培训固定口径

- **需要的内容**：面向门店老板讲「为什么在实体店买」的标准话术——不贬低线上渠道、不承诺绝对低价；强调顾客随时能找到门店、面对面服务、专门售后；重点是老客客情维护、复购提醒、问题处理与可信赖服务，而非单次价格对抗。
- **为什么记**：销售面对「线上更便宜」质疑时的标准应答。AI 发现销售贬低线上或空口承诺低价时，推送正确口径纠偏。与「销售一定不能说」同源（红线反面 = 规范正面）。

### 2. 合规讲解标准（规则卡）

- **需要的内容**：DSR 必须能向门店讲清的「已审规则卡」——下单与门店操作规则，含补税、报关/申报要求等，附规则版本号与更新日期。
- **为什么记**：门店问「怕被查」「要不要补税」是高频合规场景。AI 先检查销售是否已正确讲解，未讲/讲错/回避则生成补讲与培训任务。规则卡内容必须品牌方审定，AI 不得自行编造或解读法规（铁律：不编造公司政策）。规则版本同时用于追踪销售培训状态。

### 3. 供应链回应标准

- **需要的内容**：当期已确认的仓配能力、正常到货时效、订单查询路径、异常处理方式。
- **为什么记**：门店提「断货/到货慢」时销售的标准应答。时效只能引用当期已确认政策，禁止随口承诺（如「三天到货」必须可核实）。

### 4. 价格治理流程

- **需要的内容**：门店反映「其他渠道/线上更便宜」时的完整处理流程——DSR 必收证据清单（渠道/平台、店铺名或链接、商品规格、页面价格、发现日期、截图、门店区域、受影响 SKU）→ 总部/分销核实 → 治理/举报 → 结果回传门店。
- **为什么记**：不能仅凭口述认定破价。证据清单与流程是销售执行标准，AI 可检查执行是否到位。

### 5. 陈列物料申请流程

- **需要的内容**：门店提出陈列物料/空罐需求时的标准流程——申请 → 配发 → 二访验收的时间要求（如 48 小时内申请、7 天内二访）与动作。
- **为什么记**：销售承诺物料后的执行标准，AI 可据此检查承诺是否兑现。

### 6. 系统操作 SOP

- **需要的内容**：门店下单、查单、售后的操作指引（一页纸 SOP 的内容）。
- **为什么记**：门店说「系统记不住、太麻烦」时的标准化解答与现场陪跑内容。

## 新增库内容需求（来源：6 项「必须接入」需求文档）

### categories/（需求 1：类目打标与场景归因）

- 14 类目（价格敏感/利润/库存风险/物流/售后/合规/培训/系统工具/控价防窜/客户资产保护·飞单/线上获客/经营压力/决策链/合作模式）每类：定义、识别线索、边界、正反例、相邻类目辨析
- 为什么记：类目打标是判断任务，正反例是锚点；评测早建议扩类目（品类拓展/获客引流），与需求同向；内容按 14 类收，打标仍按 9 类（双口径）
- 需品牌方提供正反例语料

### sop/talktrack/（需求 2：核心金句）

- 话术效果条目：拜访场景 / 客户异议 / 标准话术 / 客户即时反应 / 是否听懂与接受 / 后续动作 / 最终推进结果 / 专家评价 / 适用边界
- 为什么记：金句判定标准已有；话术效果库的真正价值是「发现话术差→推送标准话术」的纠偏闭环 + 政策校验（金句不得违反产品政策）
- 需区域经理/品牌方提供话术样例；政策校验引用 `product/policy/`

### scoring/（需求 3：合作进展评分）

- 专案目标 + 6 阶段（首次触达/需求确认/方案介绍/注册操作/复访/成交）各阶段：目标、应完成动作、加减分标准、禁止项、优秀样本；评分口径：沟通质量 × 业务推进结果双维拆分
- 为什么记：评分需要「效果模型」对照；用户决策：以需求为准，评分维度重新设计（后置），知识库先行
- 需品牌方提供加减分标准与优秀样本

### sop/action-qc/（需求 4：下一步行动·区域经理侧）

- 拜访阶段 × 客户类型的推荐动作：应追问问题 / 需携带资料 / 异议处理 / 跟进时限 / 成功标准 / 无效动作 / 优秀案例；每动作有「为什么做」+「做到什么程度算完成」
- 为什么记：= 行动策略语料库 V2 的结构化扩展；注意 next-action 提示词极简定稿，注入内容限定「推荐动作+完成标准」，输出格式不动

### organization/raci/（需求 5：下一步行动·后台内部人员）

- RACI 问题域：问题类型 / 主责 / 协同 / 输入 / 交付结果 / 时限 / 异常升级（注册失败→技术、价格利润→商品、代运营开户→运营、政策承诺→合规）
- 为什么记：任务日志记录过模型编造「区域经理/运营部门/客服部门」角色——组织知识缺失是实害；归属编错会造成错误指派
- 需各后台部门供稿

### organization/service-catalog/（需求 6：后端协同支持指派）

- 服务目录（静态）：可承接事项 / 服务范围 / 当前有效流程 / 所需材料 / 标准处理时间 / 替补与升级机制；通讯录（动态）放飞书表，各部门共同维护
- 为什么记：指派需要知道后台能承接什么；通讯录是数据不是知识，不进知识库
- 输出形态（独立第 8 模块 or next-action 扩展）**待定**
