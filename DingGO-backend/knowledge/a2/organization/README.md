# organization — 组织职责

## 收录范围

需求 5（组织职责与 RACI）+ 需求 6（后台服务目录＋岗位通讯录）的知识底座：

- `raci/`：问题域条目（如注册失败→技术、价格利润→商品、代运营开户→运营、政策承诺→合规），每条：问题类型 / 主责 / 协同 / 需要输入 / 交付结果 / 处理时限 / 异常升级给谁
- `service-catalog/`：后台服务目录（静态部分）：可承接事项、服务范围、当前有效流程、所需材料、标准处理时间、替补人员与升级机制（服务目录总表 + 分服务条目）
- `通讯录指引.md`：动态通讯录放飞书表格（表 ID/URL/更新频率/维护 owner/未命中兜底），知识库只放「怎么查」，不放「人名单」

## 排除边界

- 人员名单、联系方式、当前值班安排等动态数据——飞书表格，不进知识库（数据 ≠ 知识）
- 具体话术——归 `sop/`

## 生命周期与修改检查单

- 新增条目：新开 ID `organization-<topic>-<seq>`、`version=1`、`status=active`；文件 `version` +1。
- 修改条目：**ID 不变**，条目 `version` +1，文件内 `## 变更记录` 追加一行。
- 作废条目：**禁止物理删除**，`status: superseded` + `superseded_by: <新id>`。
- 服务目录时限等时效内容：变更时升版本，90 天未更新触发自检告警。
- 提交前跑：`python scripts/knowledge_check.py --root <本仓库>\knowledge`。

## 消费模块

由流水线 manifest 决定。预计消费方：next-action（后台维度）、后端协同支持指派（新输出，形态待定）。
