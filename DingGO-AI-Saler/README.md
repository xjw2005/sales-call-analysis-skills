# AI 赋能销售云 · 微信小程序（前端第一版）

把现有「录音 → 转写 → 销售分析 → 门店档案」流水线的结果搬到小程序上呈现，界面参考支付宝「蚂蚁阿福」。
当前全部使用**演示数据**（`config/index.js` 的 `useMock: true`），不需要后端就能在开发者工具里点通所有页面。

## 怎么打开

1. 拉取本仓库，微信开发者工具 → 导入项目 → 目录选 `DingGO-AI-Saler/`。
2. 已配置项目 AppID（`project.config.json`），可直接真机调试。
3. 不需要「构建 npm」，没有第三方依赖。

## 页面

| 底部标签 / 页面 | 路径 | 内容 |
|---|---|---|
| 助手（首页） | `pages/home` | 参考阿福：每次新建对话，助手先问候：有今日计划报进度，有到期约定先提醒，都没有就问今天去哪个区，点选后给候选门店，勾选确定「今日计划」。欢迎卡里有一行今日提醒和两个选项。点「今日待办」→ 对话里出现一张大卡片（今日计划、到期的约定和跟进、待处理录音，可直接完成/复制话术/去录音）；点「AI 销售陪练」→ 进入对话内陪练（选场景 → 用底部输入框回答（老板谈出结论或最多 8 轮自动结束，也可点「结束并点评」）→ 点评卡，可退出）。输入框保留自由提问；☰ 抽屉里有陪练入口、对话记录 |

| 拜访 | `pages/visit/list` | 拜访记录，按 全部/待确认/处理中/已完成/无效 筛选 |

| 添加门店 | `pages/store/edit` | 名称、省市、地图选址 |
| 助手记住了什么 | `pages/memory` | 「我的」里进入：待确认的记忆（记住 / 不用）、已记住的别名（修改、删除；经理可设为团队通用）、手动「教助手一个说法」。对话里助手想记住某个说法时会弹出确认卡 |
| 绑定账号 | `pages/bind` | 第一次使用、微信还没绑定到人员时自动进入：输入管理员发的 8 位绑定码，成功后进入首页 |
| 进店前简报 | `pages/brief` | 门店画像、上次没做完的事、本次目标、该问的问题（按档案「未确认」维度生成）、可能遇到的异议 |

## 连接真实后端（DingGO-backend）

1. 按 `DingGO-backend/README.md` 把后端部署到服务器。
2. 改 `config/index.js`：`useMock: false`，`baseUrl: 'http://服务器公网IP:8000'`。`mockAI: false`（首页问答走后端大模型；服务器没配置密钥时会提示）；`mockPractice: false`（陪练由后端大模型扮演客户并点评；改成 `true` 则用本地演示数据）。
3. 开发者工具「详情 → 本地设置」勾选「不校验合法域名…」；手机上用真机调试。
4. 首次请求会自动 `wx.login` 登录，凭证存在本机。

## 后端需要提供的接口（`useMock` 改为 `false` 后调用）

| 接口 | 用途 |
|---|---|
| `POST /chat` `{question, storeId, history}` → `{text, suggestions}` | 首页 AI 问答（后端接大模型，结合门店数据作答） |
| `GET /assistant/today?storeId=` → `{hint, stat, steps, sections, suggestions}` | 首页「今日待办」大卡片 |
| `GET /assistant/brief/:storeId` | 进店前简报 |
| `GET /todos`、`POST /todos/:id/done`、`POST /todos/:id/undo` | 待办（后端需把“周五前”等时限解析成具体日期） |
| `GET /practice/scenarios`、`POST /practice/start`、`POST /practice/turn`、`POST /practice/finish` | AI 陪练（后端接大模型扮演客户并点评） |
| `GET /stores`、`GET /stores/:id`、`POST /stores` | 门店列表 / 详情（含档案、仪表、行动）/ 新建 |
| `POST /stores/:id/corrections` | 门店档案纠正 |
| `POST /visits` → 含 `upload: {uploadUrl, formData}` | 新建拜访并返回录音上传凭证 |
| `GET /visits`、`GET /visits/:id` | 拜访列表 / 详情（状态、模块进度、分析结果、转写） |
| `POST /visits/:id/confirm-cost`、`POST /visits/:id/rejudge` | 确认识别费用 / 重新判定有效性 |

返回字段结构以 `model/analysis.js`、`model/seed.js` 为准，与 `sales-call-analysis-scripted/references/output-spec.md` 一一对应。

## 还没做 / 要真机验证

- 登录（`wx.login` 换 token）、区域经理角色。
- 息屏或切后台时录音是否持续，需要真机测试。
- AI 问答和陪练已接入后端大模型；`useMock: true` 时仍是本地演示数据。陪练的老板台词暂不是流式输出；演示模式（mock）的陪练仍是固定 4 轮脚本。
- 简报里的问题、异议话术来自 `utils/playbook.js` 固定话术库，后期可由大模型按门店情况生成。
- 主动提醒推送到微信需用订阅消息（一次性订阅），尚未接入。


## 待办的口径

「待办」在三个地方出现，用的是同一个定义：**今日计划里要去的店 + 未完成的跟进事项（拜访分析生成的行动 / 约定）+ 等你确认费用的录音**（飞书导入的历史录音不算）。

- 首页「今日待办」卡片：只列今天要处理的（到期或快到期的跟进事项）。
- 「我的待办」页（首页卡片的「查看全部待办」、「我的」页的「我的待办」都进这里）：三类全部列出，「待办 N」是三类之和；「已完成」里是今日已去的店和已完成的跟进事项。
- 「我的」页入口上的红色数字：同一个 N。数据由 `services/todo.js` 的 `loadTodoCenter()` 统一取。

## 拜访打卡位置（定位）

录音页有一行「打卡位置」（选填）：开始录音时自动获取手机当前位置，提交拜访时一并交给后端（`checkin.lat / lng / address`），拜访详情里显示，有坐标时点「在地图上看」用微信地图打开。

- **不会阻塞任何流程**：没授权、定位失败、接口没开通，录音和提交都照常；只有用户自己点「获取当前位置」被拒绝时才弹说明并引导去设置，自动定位失败只在这一行提示。
- **备选**：点这一行可以「在地图上选择位置」（和门店地址选点用的是同一个接口），也可以清除位置。手选的位置不会被自动定位覆盖。
- 登记「没有录音」的拜访时也会尝试定位（最多等 6 秒）。
- 坐标用国测局坐标（gcj02），和微信地图、腾讯地图一致。后端校验：纬度 -90~90、经度 -180~180、地址不超过 255 字。
- 目前只显示坐标，没有「坐标 → 文字地址」的转换，也没有「离门店多远」的判断：这两项需要腾讯位置服务的 Key 和门店的坐标数据。

**上线前必须在微信公众平台处理（我没法代做）：**
1. 「设置 → 服务内容声明 → 用户隐私保护指引」里补充收集「位置信息」，并写明用途（拜访到店打卡）。否则 `wx.getLocation` 会被拦截（报 `privacy` / `not declared` 一类错误）。
2. 「开发管理 → 接口设置」里确认 `wx.getLocation` 是否需要申请开通；个人主体可能不支持。不支持时，小程序会自动退回到「地图选点」。

## 回到顶部

拜访列表、门店列表、门店选择这三个长列表页，往下滚过一屏后右下角出现「回到顶部」按钮，点一下平滑回顶（组件 `components/back-top`，滚动判断在 `utils/backtop.js`，只在跨过阈值时刷新页面）。底部标签栏里点已选中的标签，也会回到顶部。新的长列表页照这三页的写法接入即可：页面 `onPageScroll` 里调 `trackScroll`，json 声明组件，wxml 放 `<back-top show="{{showTop}}" />`（底部有固定按钮或没有标签栏时用 `offset` 调位置）。

## 门店列表缓存

真实模式下，门店列表（上千家）在内存里缓存 60 秒，首页、门店页、录音页、门店选择页共用同一份，不再每次切页面都重新拉：

- 同时有多个页面要时只发一次请求；有效期内切页面不再请求。
- 新建门店、提交档案纠正、新建 / 确认费用 / 重试拜访后立即失效，马上看到最新数据。
- 换了登录的人（绑定、换号）立刻清空，不会串到下一个人。
- 缓存过期后刷新失败，先用旧数据，不会出现空白；门店页切回来先显示旧数据再后台更新，也支持下拉强制刷新。
- 演示模式不缓存；缓存只放内存，小程序被关掉就失效。有效期在 `services/store.js` 的 `STORES_TTL` 调整。

## 自动测试

页面逻辑（首页对话、切换 / 新建 / 删除对话、陪练、「我的」、录音上传重试、绑定账号等）有一套不依赖微信开发者工具的测试，用 Node 模拟 `wx` 和 `Page`：

```bash
cd DingGO-AI-Saler
node --test "tests/*.test.js"      # 需要 Node 18 及以上
```

`tests/` 已在 `project.config.json` 里设为打包时忽略，不会进入小程序包。改了页面逻辑后先跑一遍；新增交互时在 `tests/` 里补一条对应的用例。
