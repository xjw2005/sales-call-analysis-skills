# 唯一任务：门店档案（动态更新）

参考知识库（产品/类目）仅用于识别门店品类、品牌与经营模式；档案内容必须是录音证据，不得把产品卖点写成门店事实。

生成本次录音的门店档案，最终展示固定为七个维度，不得增减：一句话画像、门店基本信息、主营品类与品牌、经营模式、选品偏好、利润偏好、合作偏好与排斥项。

模型只生成一句话画像和六个事实 section；关键证据由脚本依据证据 ID 确定性生成并写入「门店档案-原文证据」字段，档案口径与来源由脚本写入。六个 section 键必须齐全；本次未提及时 `content` 写 `未确认`、`state_type` 写 `未确认`、证据为空。

## 动态更新规则（用户消息中可能提供该门店前3天内最近一次拜访的档案）

档案是跨拜访动态更新的，不是每次重新生成：

- **前次已确认、本次未提及的事实**：保留前次内容（`state_type` 沿用前次的 稳定档案），不必因本次未谈而改写成 未确认；
- **前次「待核验」或「未确认」、本次有新证据**：升级为 当前状态 或 稳定档案，用本次证据支持；
- **本次与历史冲突**：以本次新证据为准，按本次证据支持的 当前状态 写入，不保留旧结论；
- **本次新出现的事实**：正常新增；
- 用户消息未提供历史档案时，本次为首次建档，正常按单次录音生成。

一句话画像同样按动态更新规则合并（描述门店当前的总体情况，不写历史已过时的内容）。

## 其余硬性规则（不变）

- 只写对下次销售仍有价值的信息，不整段复制其他分析字段。
- 用户消息可能提供「门店档案纠正（DSR填写）」：是销售人工填写的门店事实补充与修正，权威性高于现场速记与转写，冲突时以纠正为准；纠正中与档案维度相关的门店事实（面积、主营品项、销量规模、合作状态等）应写进对应档案维度，`evidence_ids` 留空、`state_type` 用 稳定档案；纠正中的行动推进类信息（如「对接月度任务」「跟进赠品」）不属于档案维度，不得写入档案正文。
- 一句话画像和事实章节的事实来源按优先级：门店档案纠正（人工权威）＞ 门店主档地址（可信已知）＞ 本次客户证据（必须引用）；销售提问、介绍和利润测算不能证明门店事实（只能作为语境）。本次新事实必须有本次客户证据，`evidence_ids` 非空。
- 不推断极度焦虑、认真倾听、情绪激动等心理状态。
- 飞书行定位元数据不会作为客户事实输入，脚本会另行写入档案口径。
- 门店地址（门店所在省、详细地址）由脚本从门店主档清单注入用户消息，是可信已知事实：写入门店基本信息时可直接引用，无需录音证据支持，`evidence_ids` 留空、`state_type` 用 稳定档案；区域（商圈、地段等分析性描述）与门店类型推断仍须逐字出现在对应客户证据中。
- 不输出老板/关键联系人、运营与工具能力、合规与经营风险、销售接手建议、证据边界、需求明确度或当前执行状态等已删除维度。
