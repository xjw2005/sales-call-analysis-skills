# 唯一任务：门店档案（日常拜访·累计更新）

参考知识库（产品/类目）仅用于识别门店品类、品牌与经营模式；档案内容必须是录音证据，不得把产品卖点写成门店事实。

本次是**日常记录追踪拜访**（非首访破冰），门店已有历史档案。任务以**累计更新**为主：

- 用户消息中提供该门店**前三次拜访的门店档案**（各标注进店时间）。以前三次档案为基础，总结成当前门店档案的新内容，并补充本次新出现的细节。
- 前次已确认、本次未提及的事实：保留（`state_type` 沿用前次的 稳定档案）。
- 前次待核验、本次有新证据：升级为 当前状态 或 稳定档案。
- 本次与历史冲突：以本次新证据为准，按 当前状态 写入。
- 本次新出现的事实：正常新增。

## 日常拜访的详略要求

- **这是一次日常拜访，不需要分析出太多细节**：重点了解门店现在的基本情况即可。
- 在了解基本情况的前提下，**尽可能多补充本次对话中出现的新细节**（新品项、价格变化、经营调整、人员变动、合作进展等对下次销售有价值的信息）。
- 不整段复制历史档案原文；保留仍有价值的内容，用更简练的表述并入。

模型只生成一句话画像和六个事实 section；关键证据由脚本依据证据 ID 确定性生成并写入「门店档案-原文证据」字段，档案口径与来源由脚本写入。六个 section 键必须齐全；本次未提及时按上述累计规则处理（前次有确认则保留，否则 `content` 写 `未确认`、`state_type` 写 `未确认`、证据为空）。

## 其余硬性规则（不变）

- 只写对下次销售仍有价值的信息，不整段复制其他分析字段。
- 一句话画像和事实章节只能由本次客户证据支持；销售提问、介绍和利润测算不能证明门店事实。
- 不推断极度焦虑、认真倾听、情绪激动等心理状态。
- 飞书行定位元数据不会作为客户事实输入，脚本会另行写入档案来源。
- 地址、区域和门店类型必须逐字出现在对应客户证据中。
- 不输出老板/关键联系人、运营与工具能力、合规与经营风险、销售接手建议、证据边界、需求明确度或当前执行状态等已删除维度。
