# 唯一任务：九类客户关心点

`categories` 必须包含以下九类且每类一次：价格敏感、物流时效、控价防窜、培训支持、售后保障、合作模式、利润空间、系统工具、其他。

- 状态只能为 `是|否|证据不足`。
- `是`：至少一条客户询问、回应、比较、异议或决策表达。
- `否`：完整可用录音中没有客户相关表达。
- `证据不足`：仅用于录音不完整、角色无法确认或 ASR 严重损坏。
- `其他=是` 时必须填写具体子类。
- 客户明确说到价格战、价格打穿、乱价、控价或红线价时，`控价防窜`必须为是；没有窜货证据时不能扩展为防窜需求。
- 同一原话可支持不同类目，但每个类目的对象和原因必须不同。
- 做最终一致性检查：`status=是` 的 `evidence_ids` 在应用 `_scope.role_corrections` 后必须全部属于客户，且不能落入 `_scope.exclusions`。若某条证据被你纠正为销售或旁人，必须从客户证据中移除；没有剩余客户证据时将该类目改为“否”，不得让角色纠正与证据引用自相矛盾。

类目口径：

- 价格敏感：进货成本、终端售价、消费者接受度、比价、低价竞争。
- 物流时效：发货仓、配送时效、断货、现货、应急调货。
- 控价防窜：价格体系、红线价、乱价、低价冲击、窜货管理。
- 培训支持：产品培训、员工培训、销售技巧和话术支持。
- 售后保障：退换货、临期、日期、质量争议、厂家承接。
- 合作模式：压货、陈列、扫码、付款主体、佣金、返利、启动条件。
- 利润空间：毛利、净利润、推广费、租金、动销和售后成本后的真实收益。
- 系统工具：APP、后台、二维码、线上下单和操作衔接。
- 其他：前八类无法覆盖的具体经营问题。

```json
{
  "_scope": {},
  "concerns": {
    "categories": [{
      "name": "价格敏感",
      "status": "是|否|证据不足",
      "subtype": "",
      "evidence_ids": ["U0001"],
      "scene": "",
      "object": "",
      "reason": ""
    }]
  }
}
```
