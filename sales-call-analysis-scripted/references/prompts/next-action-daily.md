# 唯一任务：下一步行动策略（日常拜访）

参考知识库（RACI）仅用于问题归属判断，不得编造时限、政策、流程细节。

本次是**日常记录追踪拜访**（非首访破冰）：已建立联系、存在历史行动记录。任务分两部分，同一次分析输出两个字段：
1. `closure`（写飞书「上一次行动与这一次行动总结闭环」字段）：记录上次行动完成情况 + 本次拜访销售与 DSR 实际做了什么；
2. 行动策略（写飞书「下一步行动策略」字段）：基于闭环结果输出下一步行动。

用户消息中可能提供该门店**前一次拜访的下一步行动策略与总结闭环**，作为判断上次行动完成情况的依据。本次**不判定合作状态**（不写「是否达成合作」）。

## 总结闭环（closure）

- `closure.summary`：一句话总结本次日常拜访中销售/DSR 实际做了什么（推进了什么、解决了什么、交付了什么）。
- `closure.items`（0 至 3 条）：逐条判断**上次行动策略中的每项行动是否完成**。
  - 已完成：`done` 写`已完成`，`evidence_ids` 引用本次对话中的完成证据（客户确认、销售执行记录等），`reason` 可留空；
  - 未完成/部分完成：`done` 写`未完成`或`部分完成`，`reason` 必须说明原因（客户原因、外部条件、未跟进等），`evidence_ids` 可空。
- 用户消息未提供上次行动策略时，`items` 输出空数组，`summary` 只总结本次做了什么。

## 行动判断

- `action_judgment`只能为`触发/不触发/待验证`。
- `触发`：闭环显示存在未完成事项，或对话结束后存在明确待办、未闭环断点；至少有一条`confirmed_actions`或`recommended_actions`。
- `不触发`：上次行动已闭环且本次无新增待办；两类动作均为空。
- `待验证`：录音信息不足以决定是否跟进；两类动作均为空，在`judgment_reason`中明确缺少什么信息。
- `judgment_reason`用一至两句话说明判断依据（如「上次行动已完成，本次新增……」），不复制时间戳或发言ID。

## 已确认的下一步

- 只写在本次对话结束之后仍待执行，且由客户亲口答应、销售明确承诺或双方当场约定的后续动作。
- 现场已经完成或正在执行的事项不得原样写成下一步。
- 客户仅以“嗯、好、行”附和销售提出的任务，不构成客户明确承诺。
- 时间按对话原意填写；对话没有时间时写“未明确时间”。

## 建议行动（recommended_actions）

- 0 至 3 条，**直接对应闭环中的未完成事项或本次新出现的断点**，不写与对话无关的泛泛建议。
- 上次行动未完成：先写完成该行动的具体动作（重新联系、确认阻塞原因、更换负责人等）；连续两次未完成同一行动时，判断是建议不现实、找错决策人还是需要管理资源，写进`reason`。
- 上次行动已完成：写推进下一阶段的具体动作（试用→首单、首单→复购、培训→落地等）。
- 每条必须包含`topic`、`owner`（销售/区域经理/双方）、`timeframe`、`action`、`reason`、`acceptance`（可观察、可确认的完成标准）。
- 必须评估二次拜访价值：`second_visit.value`从`值得/暂缓/不建议/无法判断/不适用`中选择。
- 需要外部政策、价格、库存或公司资源时，写成“确认并发送……”或“向公司确认……”，不得编造数字或既有能力。
- 不写对话中完全没有出现过的新举措，不使用“保持沟通、持续跟进”等泛化表述。
